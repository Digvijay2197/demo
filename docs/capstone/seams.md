# Seam list — where the parts did not fit

> Written 2026-10-12 while integrating (every entry is a seam that actually bit during the build, in the order it was hit).
> The brief wants this "Tuesday, unedited": **re-date and re-read it yourself before submitting** — I have only
> added the final status column after fixing, and the commit history shows when each fix landed.

| # | Seam (between what and what) | What went wrong | Status |
|---|---|---|---|
| S1 | **CMS ↔ everything**: `recipe_id` is not unique — 8 recipes exist as two versions | A lookup by id alone returns "whichever row came first" (the original = the superseded one). This is the client's actual shortbread bug, reproduced at the data layer. | **fixed** — `version` is a first-class argument (enum in the MCP schema); `CAPSTONE_VERSION_POLICY=resolved` defaults to *current*; the naive policy is kept as the measurable BEFORE |
| S2 | **Week 4 retriever ↔ new corpus**: RRF keys chunks by `chunk_id`/`source_file::page` | New records had neither, so every chunk collided on `None::None` and fusion returned **one** hit for every query | **fixed** — `chunk_id = "<recipe_id>@<version>"` on every indexed record |
| S3 | **Agent ↔ MCP server**: first tool call | The embedding model loaded lazily *inside* the first call on the stdio event loop: 160–500 s (the same load takes ~40 s in a plain process). The agent's 120 s wall-clock budget then killed the request and returned an empty answer. | **fixed** — server preloads the retriever on the main thread before `mcp.run`; connect is ~9 s, calls are ms |
| S4 | **LLM ↔ citation parser**: citations as text | gpt-oss-20b writes `R‑101@reformulated‑2025` with U+2011 non-breaking hyphens, and sometimes `( )` instead of `[ ]`; the regex saw zero citations and the case "failed" for the wrong reason | **fixed** — `guards.norm()` folds typographic characters; the regex accepts optional brackets |
| S5 | **Agent ↔ MCP ↔ logging**: the trace id lives in the agent process; the tool runs in another | Nothing connected a server-side span to the request | **fixed** — every tool takes `trace_id`; the client injects it (stripped from the schema the model sees so it can't invent one); server writes spans with it; `obs.load_trace` joins the two logs |
| S6 | **Week 11 tracing ↔ health data**: old tracer stores the raw question and answer | A stated allergy ("my daughter Priya is allergic…") would be written to disk verbatim | **fixed** for the capstone (`obs.py`: redact names/relationships/ages/contacts, no raw user id). **accepted** for the old PDF chatbot's `rag/observability` — it still logs raw questions; out of scope here |
| S7 | **Redaction ↔ the answer**: names echo back | Unit test caught `"Hi Arjun's mum"` surviving redaction because only the question was parsed for names | **fixed** — names found in the question are scrubbed from the answer too. Best-effort regex; see weaknesses.md #3 |
| S8 | **Budget ↔ cold start**: wall-clock budget started before the server was warm | (same root cause as S3, different symptom: `terminated_by=wall_clock_s`) | **fixed** |
| S9 | **Week 7 tools ↔ Week 12 tools**: `agent/tools.py` has a 6-recipe in-code book, `AllergenClass` enum, no versions | Could not be reused for a versioned corpus | **accepted** — kept untouched (Weeks 7-10 numbers must not move); capstone tools are new and call `capstone/domain.py`. The Week 7 *loop shape* and `Budget` are reused |
| S10 | **Two price tables**: `rag/config.py` (0.075/0.30 per M) vs `agent/llm.py` (0.10/0.50) | Same model, two prices | **accepted** — capstone uses `agent/llm.py`'s; both are assumed list prices, not billed (free tier). Verify before quoting the 10× number |
| S11 | **Environment**: `rank_bm25` is in `requirements.txt` but was missing from `.venv` | Retriever import failed on a "clean" machine | **fixed** (installed); the README path now works from `requirements.txt` |
| S12 | **User's allergens ↔ model's tool args**: who decides what "the user is allergic to"? | If the guard trusted the arguments the model passed to `check_allergens`, a model that passes `[]` defeats it | **fixed** — guards re-parse the *question* deterministically (`domain.extract_avoid`); model args are never the source of truth |
| S13 | **Multi-turn memory** ("she's allergic to nuts" said three messages ago) | Each `ask()` is stateless; an allergy stated earlier is forgotten | **ran out of time** — listed as weakness #2 |
